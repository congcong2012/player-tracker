# Player Tracker Compass 玩家追踪指南针

一个 **Minecraft 1.21.1 / NeoForge** 小模组：给指南针加上「追踪某个玩家」的能力。

材质、模型、指针动画**全部复用原版指南针**（`item/compass_00` ~ `compass_31`），模组本身不含任何自制贴图。

## 环境

| 项目 | 版本 |
| --- | --- |
| Minecraft | 1.21.1 |
| 加载器 | NeoForge 21.1.255（要求 21.1.0+） |
| Java | 21 |
| 构建 | ModDevGradle 2.0.148 + Gradle 8.10.2 |

## 玩法

| 操作 | 效果 |
| --- | --- |
| 右键玩家 | 绑定目标；若该玩家已是目标，则解除绑定 |
| 潜行 + 右键（空气或方块） | 清除当前目标 |
| 手持指南针 | HUD 在快捷栏上方显示目标名与距离；指针指向目标 |

已绑定时物品带附魔光效。合成：**指南针 + 末影珍珠**（无序合成），或从创造模式「工具与实用物品」页签拿取。

### HUD 状态

| 状态 | 显示 |
| --- | --- |
| 已绑定，目标同维度 | `Steve · 128 格`（绿色） |
| 已绑定，目标在别的维度 | `Steve · 位于下界`（黄色） |
| 已绑定，目标离线 | `Steve · 离线`（灰色） |
| 未绑定 | `追踪指南针：未绑定` |
| 刚绑定 / 数据未到 | `追踪指南针：同步中…` |

指针在无有效目标（未绑定、跨维度、目标离线）时会缓慢空转，与原版指南针「找不到目标就乱转」的观感一致。

## 构建

```bash
cd E:/mcmod开发/player-tracker
./build.sh build          # 产物 build/libs/playertracker-1.21.1-1.0.0.jar
./build.sh runClient      # 启动开发客户端
```

`build.sh` 使用工作区自带的 JDK 21 与 Gradle 8.10.2，并强制 IPv4（本机 Java 走 IPv6 会连接超时）。
把 jar 丢进 `mods/` 即可，客户端与服务端都要装（服务端负责解析目标状态）。

## 实现要点

- **数据存储**：两个数据组件挂在物品上——`playertracker:target`（目标 UUID）与 `playertracker:target_name`（绑定时名字）。
  两者都 persistent + `networkSynchronized`，物品栏一变动就随容器包同步到客户端，无需额外 RPC。
- **网络同步**：服务端每 10 tick 检查主手 / 副手，把 `TrackSyncPayload`（UUID、名字、状态、维度、坐标、距离）发给持有者；
  绑定 / 解除时立即补发一次。
- **指针角度**：客户端注册 `minecraft:angle` 物品属性，公式与原版 `CompassItemPropertyFunction` 一致
  （`atan2(dz, dx)/2π` 再叠加玩家朝向）；模型 JSON 里复刻了原版 32 档 `overrides`。
- **HUD**：`RenderGuiEvent.Post` 绘制，打开任何界面或 F1 时自动隐藏。
- **安全性**：客户端类只在 `Dist.CLIENT` 侧加载；网络处理器用 lambda 延迟解析，专用服务器不会因缺客户端类崩溃。

## 已知限制

- 跨维度只提示「位于某维度」，不指路（原版指南针同样无法跨维度定位）。
- 目标在客户端加载范围外时，指针使用服务端同步的坐标，0.5 秒更新一次，转向会比近处目标略「台阶化」。
- 追踪关系存在物品上，把指南针丢给别人，对方会继承这个目标。
